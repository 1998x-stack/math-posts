# 学生视角的题目展示与逐步解题（规范 v1）

> 目标不是把解答拆成更多段落，而是让第一次遇到这道题的学生看懂“为什么能做这一步”，并且能自己检查。

## 1. 设计目标与证据边界

- **原题不可改**：原卷题干、数学符号、选项、每小问、插图及题号作为独立的“原题区”。上方可放“题意导读”，但应清晰标注为编辑解释；原题区内不要以新条件偷换原条件。
- **数学正确先于动画**：数值演示只能建立直觉，不能代替全称命题、充要性、边界或构造存在性证明。
- **双轨阅读**：初学者按“线索→步骤→检查”逐段探索；熟练者可快速跳到完整证明与答案。非 JS 环境中所有原题与证明必须可读。
- **隐含疑问显性化**：每个核心变形对应至少一个本题相关的“为什么”，而不是机械填充模板语句。
- **可溯源**：“原卷答案”“本站独立证明”“编辑补充例子/反例”使用明确的文字标签；不暗示上传 PDF 具有公共下载地址。

## 2. 页面的信息层级与渐进披露

| 顺序 | 组件 | 学生最关心的问题 | 必备内容 |
|---|---|---|---|
| 0 | 来源条 | 哪张试卷？第几题？ | 学校/地区、年份、考试、原卷题号与来源页、证据状态 |
| 1 | 题意导读 | 它到底要我算什么？ | 用朴素语言说明对象、输入、目标、难点；明确不是原题 |
| 2 | 原题区 | 真实条件是什么？ | 原文、选项、小问、原图；数学使用语义 MathML |
| 3 | 信息标注 | 哪些条件有用？ | 已知、待求、隐藏约束、符号表、定义域 |
| 4 | 思路地图 | 为什么走这条路？ | “题设 → 观察 → 方法 → 结论”的可检查路线；可给替代法 |
| 5 | 解题步骤 | 每一步的依据？ | 编号、目标、推导、依据、疑问、检查、对应图形 |
| 6 | 答案核验 | 答案对了吗？ | 标准/独立答案区分；代回、取等、特殊点、边界与反例 |
| 7 | 迁移练习 | 换个条件还能做吗？ | 1 个变式与知识标签、前置知识、相似题 |
| 8 | 证据与更正 | 这个结论可信么？ | PDF 页码、核对状态、异常符号和修订记录 |

**无 JS 保底**：将完整解题步骤放在正常 DOM（例如 `<section>`、`<ol>` 和 `<details open>`），JS 只增强逐步切换/高亮；禁止通过只在 JS 内生成答案来控制可见性。

## 3. Step Schema：每一步都要“做—因—算—查”

一个可教学的 `solution_step` 至少包含：

```json
{
  "id": "s03",
  "part": "2",
  "title": "把范围限制转为不等式",
  "goal": "把图上的可行点改写成代数区域",
  "math": ["x+y>=4", "x^2+y^2>=8"],
  "reason": "由题干单调性和对称性得到第一个不等式",
  "calculation": "展开平方差并说明等号何时成立",
  "check": "检验 x=y=2 可行；不把必要条件误当充分条件",
  "student_question": "为什么极值恰好在边界上？",
  "visual_ref": "fig-feasible-region",
  "assertions": ["边界线 x+y=4", "最近点 (2,2)"]
}
```

`math` 是语义层的数学表达（示例中以字符串表达），HTML 输出必须转成完整、结构正确的 MathML，不能把源码直接打印成视觉公式。若没有学生真正可能问的问题，可以在相邻步骤合并，**不要创造敷衍的问答**。

### 每一步的呈现合同

1. **当前目标**（1 句）：这一步解决整题的什么子问题。
2. **从哪里来**：引用具体的题设条件、定义、上一式或定理；必要条件与充分条件明确标注。
3. **关键计算**：至少保留容易出错的中间式，符号变化、分母、正负号和消元不跳步。
4. **形象解释**：图上的点/线/区域/状态与当前数学关系一一对照；图注能独立阅读。
5. **反问/常见误区**：“为什么不能直接除以 x？”“交点为什么可能不在定义域内？”等与本题真实风险相关。
6. **检查点**：代入、边界、单位、可行域、相异性、根的数目、取等条件或特例。
7. **继续按钮（增强层）**：支持上一/下一步、查看完整步骤、键盘焦点和 URL 锚点；不拦截浏览器默认查找。

## 4. 不同答题形式的设计

### 填空题

先让学生预测答案所在的形式（数值、区间、坐标、表达式或计数），再解释最短关键链；答案区区分“值是多少”和“为什么有且只有这个值”。当结果涉及区间，必须在数轴画开闭端点；当是数目，必须说明不重不漏；当是几何量，标明单位。

### 选择题

将四个选项排成可比较的判定表：每个选项对应“一句话判断依据 + 最小反例或定理 + 必要的图形状态”。不要只标“正确/错误”；若多选，应分别说明每个选项成立的条件。图形可高亮当前选项而非重新绘制四个矛盾坐标系。

### 解答题 / 多小问

按原卷小问分组：每问先写“本问目标与上一问可复用结果”，再展开独立步骤；不要把（2）的结论隐式用于（1），也不要强行一条线讲完全题。对构造和存在性问题，显示“尝试→必要条件→验证→充分性”的往返。

### 证明题

明确“要证/已知/可用定理/证明策略（正推、逆推、反证、归纳、构造）”。若有逆命题、定义域、存在量词或全称量词，必须可见。图形证明不能替代一般性证明。

### 应用题

先建立变量字典与单位，再用表格或流程图解释题意转数学模型；给出实际约束、目标函数、最优解与可行性校验。明确模型假设，不能偷偷替换现实条件。

## 5. 交互与可访问性门槛

- 步骤导航为真实 `button`，状态通知使用 `aria-live="polite"`，进度文字不能只靠颜色；可键盘操作并有明确焦点。
- SVG 附 `title`、`desc`、`viewBox` 和与正文一致的图注；控制参数时同步更新图形、数值与文字关系。
- 保留“减少动画”模式；窄屏不依赖左右并排图文，公式容器独立横向滚动且可聚焦。
- 颜色不能是唯一编码；允许图形边、点或不等式区域使用不同线型、文字或图例。
- 只展示必要交互，禁止无数学含义的拖杆或伪随机动画；提供可复现默认值和重置。
- 必须检验无 JS、无网、触屏、键盘、打印、360/390/768/1440px 布局。

## 6. 质量评分与拒收条件

| 维度 | 必过检查 |
|---|---|
| 真题忠实 | 题干、选项、小问、图形名称与 PDF 核对；缺失符号保持 draft |
| 解题可教 | 每个关键变形有本题具体依据，学生疑问非模板套话 |
| 公式语义 | 原位 MathML；指数、分式、区间和符号语义正确 |
| 图式解释 | 图形支持实际推理；图形状态和数学断言可验算 |
| 正确性 | 答案独立核验，明确边界、取等、退化和相异根 |
| 适配性 | 无 JS 仍可学习，窄屏可读，控制可键盘访问 |
| 可发现性 | 关联规范化知识标签、题型、来源试卷与原卷题号 |

满足数量门槛但图形标错、论证跳步、来源混淆或未核实符号的内容，一律不发布。
