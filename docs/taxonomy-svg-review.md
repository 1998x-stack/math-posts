# 题型 × 知识图谱及 SVG 质量复核（2026-11-21）

## 一、分类结构：不要把题型当知识领域

| 维度 | 真相源 | 作用 | 数量 |
|---|---|---|---|
| 试卷作答形式（exam format） | `content/categories.json` | 填空 / 选择 / 解答，一级页面 `question-types/` | 3 |
| 题型内编辑专题 | `categories[].topics` 与 `posts[].topic` | 每种题型下的局部编排 | 14 个本地专题 |
| 数学知识领域（knowledge area） | `content/knowledge-map.json` | 函数与导数、三角函数、数列、立体几何、解析几何、概率与统计、不等式与数学思想 | 7 |
| 数学知识节点 | `knowledge-map[].subtopics` | 难度、先修、教材主题与多对多例题 | 34 |
| 学习路径 | `content/reading_paths.json` | 人工审核的顺序性学习路线，非全部文章必须收录 | 10 |

审查起点为 82 篇 HTML，正式发布 78 篇、保留证据不足的草稿 4 篇。所有正式文章均映射至少一个知识节点。跨知识领域的文章（例如函数与不等式、圆锥曲线与数学思想）可在知识地图中多次关联，但**知识领域的文章数要去重**。

### 发现与修复

1. `question-types/` 原页面标题、面包屑和 canonical 错指“知识地图”与 `topics/`，同时出现两个看似等价的分类入口。现在将两个页面的名称、URL、说明明确分开。
2. 首页原来只能依照填空、选择、解答筛选，无法从已有知识图谱检索。新增独立“数学知识”筛选，与“试卷题型”允许叠加，筛选状态写入 URL 中的 `area` 和 `category`，返回/前进保持状态。
3. 在文章构建阶段通过唯一知识图谱派生知识领域和节点；输出文章知识定位链接，**不修改 82 篇原稿的来源证据**。
4. 相关阅读除人工审核阅读路径外，可以根据共有知识节点跨题型推荐；不再因为一道题是选择题、另一道题是解答题而漏掉对应的圆锥曲线知识联系。
5. 原知识地图有部分同一文章同时属于本领域两节点；此前领域计数统计的是“例题位次”。修改为**篇数去重**，避免用户误以为该领域有更多独立题目。

## 二、SVG：检查数学正确性和浏览器真实渲染

静态审查范围是原始 HTML 的内嵌 SVG，以及每道题独立的 `assets/cover.svg`。构建后检查发布页面的图形可见性、title/desc、滚动容器和四种视口（1440 / 768 / 390 / 360px），再单独加载所有正式发布的封面 SVG。

**明确发现的数学语义错误：黄浦区解析几何 Q20。** 原页面把椭圆 `x²/5+y²/4=1` 与双曲线 `x²−y²=1` 称为“共焦”。实际上椭圆焦距参数 `c²=5−4=1`、双曲线焦距参数 `c²=1+1=2`。原题是“椭圆两焦点成为等轴双曲线两顶点”，不是两曲线拥有相同焦点。已修正文章标题、说明和内嵌/封面 SVG 的 title/desc，保留曲线与点的既定坐标。

### 移动端质量要求

- 将图示内部保持约 720 CSS 像素阅读宽度，在 390/360px 下通过 **figure 内部横向滚动**查看，不让标注从 14px 缩小到约 6px。
- 构建时为含 SVG 的图示容器增加键盘聚焦和滚动说明；打印时恢复适页缩放。
- `scripts/audit_svg.py --strict-desc` 查语法、命名、重复 ID、局部引用及描述；`scripts/browser_smoke.py` 才检查真实图形尺寸、知识导航、移动端整体溢出和独立封面加载。
- SVG 文本边界超出图形可见框会被打印为 `SVG LABEL REVIEW` 候选，需逐个确认真实裁切；不使用删除标签或隐藏 overflow 的方式掩盖问题。
